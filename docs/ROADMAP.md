# 产品与架构演进路线

顺序：**React 后台业务闭环 → Next.js Web 门户 → RN 客户端 → Web 微前端集成**。围绕同一设备工单模型逐步扩展交付端，共用业务后端，按阶段完成可验证的增量交付。

## 当前基线

React + TypeScript + Vite 已有模块拆分、路由、表单及完整工单内存演示。NestJS + Prisma + PostgreSQL 已实现真实登录、授权设备查询、文字报修和本人记录，包含会话、数据归属、参数校验与并发防重。

首次分派、维修任务/接单、文字结果和报修用户确认完成已实现，最小文字闭环已贯通；Next.js 门户已接入登录、授权设备查询、文字报修、本人记录与完成确认。RN 已接入真实登录、会话恢复、授权设备查询、文字报修、本人记录、确认完成及维修任务查询/接单、文字处理结果；微前端主应用已集成 React 工单后台、Vue 设备台账及最小导航通信。RN 已接入待分派工单补充现场照片，Web 管理员已支持看图；Web 上传与门户附件界面、改派、退回/再次提交仍后置。

## 阶段一：React 后台业务闭环

- 小步顺序：管理员真实列表与分派 → 维修人员接单处理 → 用户确认与操作历史。先完成文字最小闭环，不等待所有设备维护、统计和附件功能完成。
- 完成标准：三角色通过真实 API 完成同一工单闭环，刷新后可追溯；服务端拦截越权、非法迁移和并发冲突，关键路径有必要测试。
- 工程重点：组件职责与状态归属、异步请求取消、权限展示、运行时参数校验和服务端事务一致性。
- 当前里程碑：最小文字闭环已完成，状态与各操作记录可刷新回看，规则见 [ADMIN_ASSIGNMENT.md](ADMIN_ASSIGNMENT.md)、[TECHNICIAN_TASKS.md](TECHNICIAN_TASKS.md)、[TASK_RESULTS.md](TASK_RESULTS.md)、[TICKET_CONFIRMATION.md](TICKET_CONFIRMATION.md)。已进入 Next.js 门户首步，不自动扩展退回或附件。
- 风险：内存演示与真实授权持续隔离；退回与再次提交需要结果批次及历史保留设计，不能覆盖原处理说明。

## 阶段二：Next.js Web 门户

- 当前里程碑：`apps/portal` 已交付登录 → 授权设备查询 → 文字报修 → 本人分页记录与详情 → 报修用户确认完成，最小文字门户闭环已完成。服务端读取、会话转发、防重和个人数据缓存边界见 [PORTAL.md](PORTAL.md)。下一阶段可进入 Expo/RN，具体首步需确认后实施；不自动扩展图片、退回或微前端。
- 到此阶段新增 `apps/portal`，面向报修用户提供登录、设备详情、报修、本人记录和完成确认。采用 App Router，明确服务端/客户端组件边界，组织动态路由、数据读取、加载与错误处理。
- 先验证“登录 → 授权设备详情”，再增加其他页面。共用 NestJS，不在门户重复实现业务规则或直接访问数据库；必要代理只承担传输适配。
- 完成标准：真实链路支持直达、刷新、退出；个人数据缓存和会话隔离明确；类型检查及生产构建通过。
- 工程重点：渲染策略、会话转发、个人数据缓存隔离和交互表单提交一致性。
- 风险与处理：独立门户 Cookie 适配现有 `/api` 会话，精确检查 Origin，个人数据禁用持久缓存；后续写业务继续复用 NestJS 幂等和状态规则，不在门户复制。
- 现有 React 报修入口保留为回归基线，用户新功能以门户为主，避免长期扩展两套相同页面。

## 阶段三：RN 客户端

- 当前增量：`apps/mobile` 已交付 Expo/RN 工程、服务首页、须知、导航、主题与安全区，完成 Android 模拟器 + Expo Go、浏览器预览及 Android JS bundle 导出；已接入原生鉴权、SecureStore、授权设备列表/详情、文字报修、本人分页记录/详情、确认完成及维修任务查询/接单、文字处理结果。独立内测 APK 已生成并在 MuMu Android 15 通过受限 HTTPS 文字闭环，实体手机与本包相机/相册仍待验证，见 [MOBILE.md](MOBILE.md) 和 [异地移动端内测](REMOTE_MOBILE_TEST.md)。
- 已接入设备二维码相机入口、编号查询及 Web 设备标签，范围与验证边界见 [MOBILE.md](MOBILE.md)。RN 已接入拍照/相册补充现场照片与维修人员查看，边界见 [TICKET_PHOTOS.md](TICKET_PHOTOS.md)；Web 管理员已接入照片只读查看与放大预览，门户附件仍后置。后端继续单一 NestJS，保留 Web Origin 防护；各步确认后实施。
- 到此阶段新增 `apps/mobile`，使用 Expo 共用 NestJS。先实现登录和文字业务，再加入扫码、拍照上传、本人报修、维修任务与处理确认；按需要补充后端上传能力。
- 完成标准：Android 优先验证关键链路及权限拒绝、网络失败处理；Expo Go、模拟器、真机、开发构建和独立安装包分别记录，未验证项明确说明。iPhone 依设备、构建和签名条件安排。
- 工程重点：相机权限、凭据安全存储、上传失败恢复及多端接口一致性。
- 风险：移动端凭据保存、会话撤销与本机网络，不能照搬 Web Cookie 假设或放宽 Web 来源校验。

## 阶段四：Web 微前端集成

- 本阶段本地交付范围已完成，采用稳定版 qiankun 2.10.16。`apps/shell` 加载 React 后台和 `apps/devices` Vue 台账的独立兼容构建，各自独立入口保留；已验证挂载、路由、权限、样式隔离、反复卸载与加载失败，并完成统一生产构建入口的深层路由、同源资源和 API 转发验证，见 [微前端集成](MICRO_FRONTENDS.md)。Next.js 门户与 RN 独立运行；服务器发布不包含在本阶段。
- Vue 已提供授权设备列表与详情，导航消息由主应用校验后打开 React 对应设备详情；已验证双应用切换与权限。后续按反馈确定发布配置或业务扩展，不提前加入复杂全局状态和跨域 SSO。
- 完成标准：独立构建、路由、登录权限、最小通信协议、样式隔离、重复挂载卸载及加载失败可验证，没有残留监听或前端权限绕过。
- 工程重点：应用生命周期、最小通信协议、路由归属和卸载资源回收。
- 风险：构建兼容、路由前缀和跨应用登录；不提前改造整个后台。

## 复用与协作约束

- 保留 npm workspaces 中的 `apps/web`、`apps/api`、`apps/portal`、`apps/mobile`、`apps/shell`、`apps/devices`、`packages/contracts`；新应用到阶段再创建，不建空目录，不引入第二套业务后端或微服务。
- NestJS 统一负责鉴权、数据归属、状态迁移、事务与防重。共享接口类型；纯规则出现真实多端消费者后再提取。界面、导航、存储和设备能力分别实现，不跨应用导入页面或共享 ORM 实体。
- 沿用后台 Ant Design、Tailwind、CSS Modules；不强行共享 Web/RN 界面。新增框架时核对稳定版本与兼容性，不批量升级现有应用。
- 不安装到 C 盘；缓存和临时文件留项目内。不自动部署、调用收费模型 API；报价、订单、支付、实时更新、大屏和 Three.js 后置。
- 业务决策、代码审核、人工验证与交付结果由维护者负责。记录实现范围、验证环境和技术取舍，独立项目成果与既有商业项目经历分别说明。
