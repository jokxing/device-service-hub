# 维修任务与接单

维修人员通过独立任务入口读取当前分派给自己的工单，并将待接单任务转为处理中。列表、详情和接单共用服务端归属条件；报修用户与管理员通过各自原有入口查看进度。

## 接口与数据范围

| 入口 | 行为 |
| --- | --- |
| `/service/tasks` | 本人任务列表，筛选与分页写入 URL；桌面表格、窄屏卡片 |
| `/service/tasks/:id` | 本人任务详情、接单确认及状态刷新 |
| GET `/api/tasks` | 仅查询 assigneeId 等于当前会话用户的工单，支持 page/pageSize/status |
| GET `/api/tasks/:id` | 工单 ID 与当前维修人员 ID 同时匹配才返回 |
| POST `/api/tasks/:id/accept` | 按请求版本接单；首次成功和同意图重放均返回 201 |

未登录返回 401，非维修角色访问任务接口返回 403。未分派给本人、尚未分派与不存在的工单统一返回 404。客户端传入维修人员 ID、角色或任意状态均不能扩大权限。

任务记录返回必要的设备信息、问题、状态、分派信息、版本和接单记录，不暴露报修账号资料、管理员分派审计、请求编号或数据库内部字段。本人报修接口继续按报修人过滤，管理员管理接口继续单独校验管理员身份。

本步任务详情包含关联设备摘要；独立设备台账的维修人员访问策略维持原有范围，没有因为开放任务而开放全部设备或同设备的其他工单。

## 状态与事务

唯一新增状态操作为 **assigned → processing**，要求当前维修人员与 assigneeId 一致、状态为待接单且版本匹配。请求为 `{ requestId, expectedVersion }`，接单人来自有效会话。

TicketAcceptance 保存工单、接单人、时间、提交编号与原版本：ticketId 唯一，同一接单人加 requestId 唯一。接单时间以数据库记录为准，不采用客户端时间。

1. 先验证当前任务归属，防止历史成功请求成为权限绕过入口。
2. 已存在同一接单人/请求编号时，校验工单和原版本，相同则返回当前任务；编号被用于不同内容时返回 409。
3. 新接单在一个事务内按 `id + assigneeId + assigned + version` 条件更新状态、递增版本并写接单记录。
4. 并发竞争失败后重新检查幂等记录：同意图返回原结果，不同意图返回 409；事务失败不留下孤立状态或重复记录。

报修用户、管理员及任务所有者的详情均从同一接单记录读取操作人和时间，避免多处维护不同时间来源。

## 异常与交互

- 过期版本、已接单或非待接单状态：409，提示关闭确认框后刷新核对。
- 参数格式错误、夹带 actorId/assigneeId/status 等额外字段：400。
- 账号停用、会话过期或退出：401，前端清理会话及旧页面内容。
- 同一确认框中的重试沿用 requestId；关闭重开为新意图。结果不明时可重试原请求，也可先刷新核对。
- 确认请求进行中禁用重复操作与关闭；离页取消请求，超时后允许重试。前端交互限制不能替代服务端版本校验和事务。
- 接单完成后重新读取列表/详情，移除接单入口。报修用户刷新本人详情即可看到处理中及接单记录。

## 工程组织

- TaskTicketsController 处理 HTTP，TaskTicketsService 处理角色、归属、状态、事务和重放；不引入通用 Repository 或任意状态修改接口。
- TicketCommandDto 复用请求编号与版本校验，分派和接单各自定义命令 DTO；StatusTicketsQueryDto 复用分页与状态校验。
- `packages/contracts` 仅共享传输类型。维修任务保留自己的响应白名单，不直接复用管理员响应。
- Web 按页面、列表、确认弹窗和 API 分工；详情字段复用 TicketRecordDetails，卡片复用 CompactRecordCard，前端接单入口共用 canAcceptTask。
- 迁移仅新增接单记录表和约束，旧迁移、账号与工单保留；迁移前备份到被忽略的 `.local/backups`。

## 验证

```sh
npm run verify:tasks
npm run verify:tasks-ui
```

Windows 通过 `.\scripts\npm-local.ps1 run <脚本名>` 执行，数据库、API 和 Web 需已启动。

API 检查覆盖本人列表与计数、分页筛选、跨维修人员、未分派工单、非法状态、版本冲突、八路同意图并发、不同意图竞争、归属变化后的重放及账号停用。浏览器检查覆盖状态过期提示、取消与重试、响应丢失、直达刷新、桌面/窄屏和跨账号页面清理。

测试仅针对专用本地数据库，临时工单按本轮随机 requestId 和报修人清理，分派/接单记录随工单级联清理；临时账号只按本轮随机 ID 删除。不会按名称、角色或标题批量删除人工数据。截图可能包含已清理的临时记录。

本步没有处理结果、用户确认、上传、改派、RN 或生产环境交付。
